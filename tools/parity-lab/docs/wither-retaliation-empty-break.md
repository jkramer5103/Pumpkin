# Wither retaliation success on unchanged fluids

A damaged Wither scans nearby blocks after twenty AI ticks. Vanilla emits its boss block-break event (1022) only if at least one block changed. Pumpkin reported success when replacing source water or lava with the same fluid state, so a fluid-only pulse emitted an extra boss sound event. A second pulse after breaking seagrass had the same problem because the remaining cell held water.

`World::break_block` now returns the previous state only when it differs from the replacement. Existing plugin cancellation, pre-write loot, flags and effect handling remain in their original order. Solid breaks still return success. Most shared callers ignore the return; mining callbacks/statistics and Wither retaliation use it to decide whether a break succeeded.

The reference is Minecraft 26.3 `WitherBoss.customServerAiStep` calling `Level.destroyBlock`. Its boolean comes from `Level.setBlock`, which returns false when `LevelChunk.setBlockState` returns null for an unchanged state. The local assignment55 provenance artifact records source/jar hashes, chunk bytecode evidence and upstream refs. Fork master was already an ancestor. All 313 open upstream PRs were screened, including the relevant world/Wither diffs in PR4092, PR3859, PR4114 and PR3826; no matching return-value fix was found.

The regression fixture is `lab/examples/wither-retaliation-empty-break.json`; `tests/check_wither_retaliation_empty_break.py` checks its packet capture. Six sealed cells cover water, lava, air, immune bedrock, stone and seagrass. Each row damages the same Wither twice, checks the block before and after tick twenty, checks its position and the bedrock seal, and captures event1022 through an actual connected protocol777 client. The stone and initial seagrass pulses must each send one event; all other pulses must send none. No event may arrive during the first nineteen ticks. The second pulse checks both removal of the stone and conversion of seagrass to water.

Before-fix comparison: vanilla passed 108/108 checks; baseline c6f054096 passed 103/108, failing exactly the five expected fluid-only sound-event assertions. Each target advanced 416 controlled ticks, with identical fixture and gameplay hashes. Cleanup, process stop, Pumpkin save/stop markers and server/client error scans passed.

Patched comparison: 108/108 checks passed, matching vanilla; baseline failed exactly the five expected assertions. All three targets used the same fixture and gameplay hashes and advanced 416 controlled ticks each. Cleanup, process stops, both Pumpkin save/stop markers and clean server/client logs were verified. Source and copied-binary hashes connect the patched capture to the Rust change. All 444 core Rust library tests, workspace formatting, core Clippy with all targets/features and the debug server build passed under the shared Cargo lock and resource limits. The existing proc-macro-error2 future-compatibility warning remains. Coverage is a focused world scenario; no new isolated Rust unit test was added.

Limitations: headless protocol/server-state evidence, no rendered audio or natural/full-fight proof. A real client can damage a Wither in a sealed water-only arena and listen after twenty ticks: no boss block-break sound should play. Replacing the water cell with stone should produce the sound on the first pulse only. Vanilla's initial fluid destroy-particle event differs separately and is outside this change. Reload, Bedrock and plugin-listener behavior were not exercised.
