# Wither duration-effect immunity

Withers could acquire duration effects from tipped and spectral arrows. Resistance V then prevented damage that vanilla still deals. Vanilla 26.3 `WitherBoss.addEffect(MobEffectInstance, Entity)` unconditionally returns false, before the shared living implementation can mutate attributes, store effects or publish effect metadata. Pumpkin calls its shared `LivingEntity::add_effect` directly, so the correction folds the Wither override into that entry point before effect dispatch. Other entity types retain their existing application and plugin event path. Instant potion application has a separate path and is outside this correction, as is restoration of effects already present in saved NBT.

The focused regression fixture `lab/examples/wither-duration-effect-immunity.json` lands real nonzero-damage arrows on stationary full-health Withers and sheep. Tipped arrows carry Resistance V or slowness; spectral arrows carry glowing. Impact health proves the arrows connected. Withers must reject each effect while sheep acquire the identical payload. After the resistance arrows, the fixture waits for the damage cooldown and restores initial health to isolate a four-point magic hit: vanilla Wither health becomes 296, while the resistant sheep stays at 8. NoAI prevents Wither regeneration and attacks; all activity takes place in isolated scratch arenas with a connected headless protocol 777 client. Two repetitions use frozen, verified ticks and cleanup between trials.

The final reference run passes 46/46 checks on vanilla and 38/46 on baseline Pumpkin. Each baseline repetition fails exactly the three Wither effect-rejection assertions and the later magic-health assertion: resistance leaves the boss at 300 instead of 296. Sheep accept all three effects on both servers. All ten numeric health observations match across the references except that intended resistance difference. Identical fixture/gameplay-command hashes, 98 verified gameplay ticks per trial, client presence, cleanup and stopped scratch processes were verified. Reference server/client logs contain no errors or panics.

All 443 core Rust library tests, workspace formatting, all-targets/all-features core Clippy and the debug server build passed under the shared build lock, one Cargo job, disabled debug information/incremental compilation, MemoryMax=5G, MemorySwapMax=0 and CPUQuota=200%. The existing proc-macro-error2 future-compatibility warning remains. The focused gameplay fixture supplies regression coverage; no implementation-mirroring Rust unit test was added.

Patched Pumpkin passes 46/46 checks and matches all ten vanilla numeric health observations in both repetitions. The eight baseline failures disappear. Built source hashes, baseline/patched binary hashes and identical fixture/gameplay-command hashes were verified. All three scratch processes stopped, with successful entity cleanup and connected clients. Server and client logs contain no errors or panics. All three servers logged saving, but complete save/shutdown markers were unverified within the existing harness grace period. Existing Java native/Unsafe and debug/offline-mode warnings remain.

Identical JARs in this lane's older scratch arenas were losslessly hardlinked after SHA-256 comparison to restore the required disk reserve; logs, worlds, reports and file paths were preserved. Initial zero-damage-arrow captures demonstrated the immunity difference but contained incorrect impact-health expectations; those reports are excluded from final validation.

Source review used upstream `998c3f872c39bb68167c6f2a47799730a23aa751`. Upstream commit `b57d821` adds narrower effect immunities but still accepts resistance, slowness and glowing on Withers. It does not implement the unconditional `WitherBoss.addEffect` rejection. Fork master `65bca3f` is already an ancestor. Open PRs [3835](https://github.com/Pumpkin-MC/Pumpkin/pull/3835), [4092](https://github.com/Pumpkin-MC/Pumpkin/pull/4092) and [3816](https://github.com/Pumpkin-MC/Pumpkin/pull/3816) cover projectile knockback/flight, AI foundations and water potions, respectively; none supplies this guard. The [tracker](https://pumpkinmc.org/tracker/) and [mob AI tracking issue](https://github.com/Pumpkin-MC/Pumpkin/issues/3468) were reviewed as leads; earlier campaign work already handles the spawn-invulnerability goal omission.

This is evidence for newly applied duration effects, not a whole boss fight. No rendered-client capture, natural potion throwing, instant potion parity, persisted-effect repair or complete Wither parity is claimed. A human visual check can hit a full-health stationary Wither and a sheep with spectral arrows: only the sheep should glow. The gameplay health regression does not require a visual interpretation.
