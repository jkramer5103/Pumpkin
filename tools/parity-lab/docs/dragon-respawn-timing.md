# Dragon respawn phase timing

Pumpkin increments `respawn_time` after the stage callback. Each transition resets the timer to zero inside that callback, and the subsequent increment overwrites the reset with one. The next phase consequently skips time zero. Official 26.3 `EnderDragonFight.tick` passes `respawnTime++` to `DragonRespawnStage.tick`: Java increments the stored field before entering the callback while passing the old value. The Rust fight now preserves that ordering by capturing the old time, incrementing the stored counter, and passing the captured value to the stage handler.

In an isolated End arena, the baseline omits the preparation's initial roar and leaves all four respawn crystal beams at the center after 105 stepped ticks. Vanilla retargets the four beams to the first pillar at tick 103. The source correction restores phase-entry effects without changing stage conditions, pillar generation or crystal selection. The world regression fixture and packet checker cover preparation roar ticks and all four first-pillar beams; they exercise actual crystal item placement and real server ticks rather than a mocked timer.

Formatting, all 493 core Rust library tests, core all-target/all-feature Clippy and the debug server build passed under the shared Cargo lock and resource limits. In the final three-target comparison, vanilla and patched Pumpkin pass both timing checks; baseline Pumpkin fails both. All nine patched preparation roar events match vanilla's exact tick sequence. All four patched pillar-beam updates arrive at tick 104, versus vanilla's tick 103; baseline has none by tick 105. Initial-boss, four-crystal center-beam, actual item-use packet, observer height, exact 105-tick interval, client, cleanup and stopped-process controls pass. All six final server/client logs are free of errors and panics; source and copied-binary hashes match the validated files. The existing `proc-macro-error2` future-compatibility warning remains. Private evidence: `artifacts/christine-dragon69-{rust-validation,live-validation,source-provenance,prepush-overlap}.json`.

The final comparison uses the same probe and conditional setup on all three targets. Portal height is discovered independently; only the placement/summon height parameters differ. The baseline binary is campaign 68, whose fight-timer source is identical to this patch's preimage, rather than a separately built upstream-master binary. An early diagnostic run missed the initial dragon and is excluded; the final probe positively requires the initial fight dragon before killing it. An earlier client launch lacked its classpath entry, and the first vanilla diagnostic observer was outside the roar event range; both are excluded from final results.

Upstream master 44d881c32 retains the old ordering. Fork master was fetched and is already an ancestor of this branch. Multipart hitboxes, damage, healing and team combat remain deferred to the existing upstream work. Limits: headless protocol 777 packet and server-state evidence, with no rendered-client, Bedrock, pillar-regeneration or complete-fight proof. Natural portal height and seed-dependent pillar height differ between targets; the check isolates phase timing and beam destination x/z. Pumpkin's independent one-tick metadata flush delay is allowed for beam packets and is not fixed here. Later respawn phases have additional unverified differences outside this bounded correction.
