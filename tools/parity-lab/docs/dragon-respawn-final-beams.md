# Final dragon respawn beam recipients

When the final respawn phase begins, the four exit-portal crystals must turn their beams from the last pillar back toward (0, 128, 0). Pumpkin instead searches every spike column and retargets the pillar crystals. The portal crystals consequently keep pointing at the last pillar. Official 26.3 `DragonRespawnStage.SUMMONING_DRAGON.tick`, at time zero, iterates the respawn crystal list supplied by `EnderDragonFight.tick`.

The correction uses the already resolved `live_crystals` list, as the other respawn stages do. It removes the spike-column search only from this phase entry. Phase timing, pillar regeneration, crystal invulnerability and final dragon creation are outside the patch.

The focused regression fixture tracks the same four crystal entity IDs from the initial center beams through the last pillar and final phase entry. It also rejects final-entry changes to unrelated pillar crystal beams. The private arena probe kills the initial fight dragon, discovers the actual exit podium, places three crystals by summon and the fourth through a real protocol 777 item-use packet, then steps exactly 507 ticks. This stops before dragon creation and final crystal explosions. The fixture permits Pumpkin's existing one-tick dirty-metadata flush delay. Portal and pillar heights depend on generation, so portal setup adapts to the discovered height and pillar controls compare horizontal destinations.

Formatting, all 493 core Rust library tests, core all-target/all-feature Clippy and the debug server build passed under the shared Cargo lock and resource limits. The official server passes both live checks; baseline Pumpkin fails both, leaving four portal beams on the last pillar while retargeting ten pillar crystals. Patched Pumpkin passes both checks: the four tracked portal crystals return to the center at tick 505, versus vanilla tick 504, and no pillar crystal beam changes occur at that phase entry. Exact 507-tick interval, actual item-use packet, initial-boss, four initial beams, last-pillar beam IDs and destinations, client presence, cleanup and stopped-process controls pass on all three targets. All six server/client logs are free of errors and panics. Source, committed-source, probe, fixture/checker and copied-binary hashes are verified. The existing `proc-macro-error2` future-compatibility warning remains. Private evidence is recorded in `artifacts/christine-dragon70-{rust-validation,live-validation,source-provenance,upstream,prepush-overlap}.json`. The baseline is campaign 69 rather than a separately built upstream-master binary; fetched upstream 44d881c32 retains the same faulty crystal selection. Fork master is already an ancestor of this branch. Open dragon/respawn/crystal PRs were checked, including 3407, 3661, 3694 and 4080; none changes these final-stage beam recipients. Multipart hitboxes and non-player collision work remain deferred to existing upstream patches. The [tracker](https://pumpkinmc.org/tracker/) and [mob AI issue 3468](https://github.com/Pumpkin-MC/Pumpkin/issues/3468) were consulted as leads.
