# Dragon flight lookup-table rotation

A hovering dragon with its target established, zero motion and yaw 37.3 or -123.4 moves in a slightly different direction on baseline Pumpkin than on official Java 26.3. In two isolated trials, all four angled samples differ in both position and velocity after exactly one tick. Cardinal flight and NoAI controls match. The largest measured position difference is approximately 0.000000457 blocks in this one-tick fixture; this is numerical trajectory parity, not evidence of a visibly different fight.

`EnderDragon.aiStep` uses `Mth.sin/cos` to compute the old-yaw direction used by alignment and drag. `Entity.moveRelative -> getInputVector` uses the same lookup table to rotate acceleration. Pumpkin's dragon-only versions used standard-library float trigonometry. Both flight calculations now use the existing `pumpkin_util::math` helpers. Input normalization, turn calculation, yaw conversion, movement order, drag, multipart placement and shared entity/living code retain their existing paths.

The regression compares the actual Rust movement method with fixed values produced by invoking official 26.3 `Entity.getInputVector` for five headings, including positive and negative non-cardinal angles and cardinal controls. It fails against the unchanged Rust calculation at yaw 37.3. Official Java/decompiled source and the oracle remain outside the repository.

Upstream master 44d881c32 retains both direct-trig flight calculations. Fork master 65bca3f7f is already an ancestor of this branch. The dragon and trigonometry PR searches and PR3407/3661 patches were checked; neither implements this flight correction. Multipart damage/healing and entity lookup remain separate upstream work. Tracker and [mob AI tracking issue3468](https://github.com/Pumpkin-MC/Pumpkin/issues/3468) supplied leads, not proof.

Validation: workspace formatting, all 493 core Rust library tests, core all-target/all-feature Clippy and the debug server build passed under the shared Cargo lock and resource limits. The two-trial patched arena matches vanilla in all 16 position/velocity vector comparisons within 1e-12; baseline fails exactly eight comparisons for the four angled samples. Cardinal, NoAI, setup, exact tick, healthy hover-phase, client and cleanup controls pass. Each target used 176 case ticks plus 40 setup and 20 cleanup ticks. Source and copied-binary hashes match the validated files. All three scratch servers and clients stopped; all six console/client logs have no errors or panics. The existing proc-macro-error2 future-compatibility notice remains. Private evidence: `artifacts/christine-dragon68-{source-provenance,before-validation,rust-validation,live-validation}.json`. Before evidence uses the previous campaign binary whose source hashes include assignment67, rather than a separately built upstream-master binary. Open upstream overlap was refreshed before push; PR3407/3661 patches remain unchanged and contain no flight-trig replacement.

Limits: headless protocol777 and precise server-state output only; no rendered-client, Bedrock, natural flight or whole-fight proof. At-target hovering isolates acceleration rotation without exercising the turn-angle calculation. The first probe launch had a Python syntax error before starting a server; the successful identical v2 stimulus is the retained evidence. The oracle initially lacked vanilla registry bootstrap and was rerun successfully after bootstrap.
