# Dragon corpse death progress persistence

Pumpkin ignored `DragonDeathTime` when loading a dragon and omitted it when saving. A corpse restored at tick 195 or 199 therefore restarted the death animation instead of disappearing after five ticks or one tick. The dragon-specific mob NBT hooks now preserve this counter, with vanilla's zero default when the field is absent.

Vanilla 26.3 `EnderDragon.readAdditionalSaveData` reads this integer with default zero; `addAdditionalSaveData` writes it. `tickDeath` increments the counter and removes the dragon at 200. The existing Pumpkin death tick path already uses the same counter. Shared mob serialization calls the new hooks after base mob fields. No shared entity code changes.

The isolated headless comparison reproduced the lifetime difference on current campaign baseline bcaf22a (binary from task20, matching the source hashes). Vanilla passed restored lifetime checks; baseline ignored progress with both NoAI settings. Two trials per counter/NoAI combination exercise loaded progress, absent-field defaults and a subsequent NBT merge that moves an existing corpse to tick 199. The permanent `lab/examples/dragon-death-timer.json` fixture asserts entity presence/removal at these boundaries.

Rust validation passed under the shared Cargo lock with one build job, disabled debug info/incremental compilation and the 5GiB/200%CPU systemd limits: 458 pumpkin-core library tests, workspace formatting, pumpkin-core all-targets/all-features clippy and debug pumpkin build. Existing proc-macro-error2 future-compatibility warning remains. Vanilla and patched Pumpkin each passed 109/109 focused checks (88 core observations plus 21 permanent-fixture checks). Baseline passed 51/109 and failed exactly 58 death-progress observations; the fixture alone caught all 6 removal-boundary regressions. Equal command stimuli, tick barriers, client presence, source/binary/fixture hashes and server/client logs were checked. All 6 scratch server processes stopped; all 4 Pumpkin runs completed shutdown. Both vanilla runs logged saving without a completion marker within the existing harness grace. The original foreground Rust validation stopped before tests completed and was rerun successfully in a detached scope. An initial fixture replay read different fixture revisions during a cleanup correction and is excluded.

Scope limits: this checks server-side corpse continuation via the actual entity NBT entry points. It does not demonstrate disk restart/chunk reload, End portal callbacks, phase persistence, a whole boss fight, particles or rendered client behavior. Phase IDs and other dragon-specific saved state remain separate candidates. For manual visual verification in an isolated arena, restore a zero-health dragon with DragonDeathTime195; its corpse should rise for five ticks and disappear, without restarting the full animation.
