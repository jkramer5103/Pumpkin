# Wither instant-effect arrow immunity

Vanilla 26.3 `Arrow.doPostHurtEffects` sends every potion effect through `LivingEntity.addEffect`, including instant healing and harming. `WitherBoss.addEffect` rejects every effect. Splash potions and area-effect clouds instead call `applyInstantaneousEffect` directly. Rejecting all instant potion sources would therefore be incorrect.

Pumpkin's shared `PotionContents::apply_effects_to` directly applies instant effects before reaching `LivingEntity::add_effect`. That bypasses the existing Wither immunity for tipped arrows. This patch adds the Wither rejection for the Arrow application source before effect dispatch. It preserves existing duration-effect rejection and leaves splash/cloud application and all other target types unchanged. The helper is called by arrows, splash potions, area-effect clouds and potion consumption; only Wither arrow calls return early. The plugin potion-effect event was already skipped for Withers by the existing `add_effect` guard; instant effects use the existing direct path without that event.

Exploratory official-server and baseline runs reproduce the issue with real tipped-arrow impacts on stationary NoAI, NoGravity Withers. From 200 health, official 26.3 finishes at 199.14 for healing I/II and harming I/II. Baseline finishes at 203.14, 207.14, 194.14 and 188.14 respectively. The physical arrow damage remains observable. Spawn-invulnerable Withers remain at 200. Exploratory zombie controls exposed separate inversion/timing differences and are excluded from the final focused regression.

The retained fixture `fixtures/wither-instant-arrow-immunity/cases.json` tests healing/harming I/II, a plain-arrow Wither control, a charging Wither control and sheep healing/harming controls, twice each. `tests/check_wither_instant_arrow_immunity.py` checks official numeric health observations, real arrow spawn packets, arena positions, initial health, active-effect absence, controlled ticks, client presence, cleanup and stopped processes. It exercises actual server/world/projectile paths. No implementation-mirroring Rust unit test is added.
