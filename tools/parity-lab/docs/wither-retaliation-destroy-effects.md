# Wither retaliation destruction effects

A damaged Wither scans nearby blocks after twenty AI ticks. Vanilla sends the block destruction effect before attempting to replace each non-air, non-immune block with its fluid state. That effect also occurs when the fluid replacement changes nothing. Pumpkin suppressed those fluid effects and used Java particle-only event 2014 instead of the particle-and-sound event 2001 for successful breaks.

`World::break_block` now sends the existing edition-specific effect before loot and replacement, using the original block state. Java uses the generated `ParticlesAndSoundDestroyBlock` constant. Fire/soul-fire suppression, spawn protection, plugin cancellation, player audience exclusions, Bedrock's existing event constant, loot flags and mutation-based return value remain. The Wither boss event 1022 still requires a changed block.

Reference: Minecraft 26.3 `WitherBoss.customServerAiStep` calls `Level.destroyBlock`; that method calls `Block.spawnDestroyParticles` before loot and `setBlock`. The base block sends event 2001. LiquidBlock inherits the base effect; BaseFireBlock overrides the effect to do nothing. Local assignment56 provenance records jar/source/bytecode hashes. The tracker and Mob AI issue 3468 were reviewed as leads; prior campaign patches already implement the spawn-window goals. Fork master is an ancestor. All 313 open upstream PRs were screened, including the relevant world diff in all 139 PR4092 file records and PR3859/4114/3826/4058/3637/3415; no equivalent destruction-effect patch was found.

The shared API has 64 direct call sites across 43 files: mining, support loss, fluid replacement, commands, block interactions and Wither retaliation. These callers now receive the vanilla destruction effect before mutation. Return semantics stay unchanged; cancelled breaks and air emit no effect. No other callers were edited. Actual plugin listeners and Bedrock were not exercised.
