# Wither ranged navigation after a goal interrupt

`RangedAttackGoal.stop` now clears its cached victim, sight counter and attack timer while retaining the navigator route, matching vanilla 26.3. A Wither interrupted by its priority-zero invulnerability goal can continue an existing route. Previously the ranged goal also cancelled navigation, producing an early horizontal stop. The ordinary five-visible-tick navigation stop in `tick` remains in place.

The reference is the locally decompiled official 26.3 `RangedAttackGoal.stop` and `WitherBoss.registerGoals`. The fork master was fetched and is already an ancestor of baseline `314d434de1c6a32152ee00c84142bcc184bdbe2c`. Current upstream retains the extra cancellation. Open PR4092 changes navigator locking while preserving cancellation; PR4107 does not change this stop behavior. A separate dying-target eligibility defect found during investigation exactly overlaps open PR3815 and was excluded.

The regression fixture is `lab/examples/wither-interrupted-ranged-route.json`; its report checker is `tests/check_wither_interrupted_ranged_route.py`. In a sealed scratch arena with an actual headless protocol 777 client, a Wither routes toward a living sheep for two ticks. The fixture then sets Invul200 before the ranged goal's five-visible-tick stop. Six position samples over 24 controlled ticks distinguish continued routing from coasting. Each case runs twice. Ordinary ranged controls end after eight observation ticks, before side-head explosions can affect motion. Initially invulnerable controls run for 24 observation ticks. The sheep has 1000 health and full knockback resistance. The checks cover entity tracking and main-head metadata, victim presence and health, observer game mode, boss bounds and AI state, invulnerability countdown, cleanup and server/client logs. Each complete target run advances 300 controlled ticks including cleanup.

Rust validation passed under the shared Cargo lock with one build job, debug information and incremental compilation disabled, MemoryMax=5G, MemorySwapMax=0 and CPUQuota=200%: workspace formatting, all 444 core library tests, core all-target/all-feature Clippy and a debug server build. The existing proc-macro-error2 future-compatibility notice remains. No new isolated Rust unit test was added; the world-fixture regression detects the observed gameplay difference.

Final identical-fixture comparison: vanilla 92/92, baseline 90/92 with exactly the two interrupted-route checks failing, patched 92/92. Interrupted horizontal travel was about 1.99–2.02 blocks on vanilla, 0.08–0.24 on baseline and 2.06–2.12 after the fix. The patch restores route continuation; the remaining numeric trajectory difference is outside this correction. Ordinary ranged and initially invulnerable controls passed on all three targets. Fixture/stimulus/source and copied-binary hashes, all 300 controlled ticks per target, cleanup, clean client/server logs, and stop/save log markers were verified. The regression fails against the prepatch binary and passes against the patched binary.

This fixture forces midlife invulnerability to isolate a goal-stop contract; it does not establish natural construction, target-death behavior or whole-fight parity. Speeds and NoGravity are controlled. Remaining flight/controller/gravity differences are outside this patch. Witches, snow golems, llamas and trader llamas share this goal but have no live gameplay comparison here. There is no rendered-client or Bedrock proof. An earlier ordinary ranged control ran long enough for side-head explosions and is excluded; the final control stops before those attacks. The target-death discovery was masked by corpse eligibility and the single-client logout discovery lost its observer; neither supplies regression evidence. Decompiled Java, scratch probes, worlds, binaries and credentials are excluded from the commit.
