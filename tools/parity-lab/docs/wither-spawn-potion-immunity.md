# Wither spawn-phase potion immunity

Instant potion damage now dispatches through the actual entity, so a Wither's existing spawn-invulnerability gate can reject it. The shared potion dispatcher previously damaged its embedded `LivingEntity` directly, bypassing mob overrides. Splash, cloud, arrow, consumption and witch callers now pass their existing dynamic entity reference. Healing and duration effects still use the embedded living state; arrow-effect rejection for Withers remains before application.

Official 26.3 `HealOrHarmMobEffect.applyInstantaneousEffect` calls virtual `hurtServer`; `WitherBoss.hurtServer` rejects ordinary damage whenever `getInvulnerableTicks() > 0`. The official Java source was decompiled outside Git. Pumpkin already has the equivalent gate in `WitherEntity.pre_damage_with_context`, reached by the blanket mob damage implementation. This correction restores that dispatch instead of copying an immunity check into potion code. Other mobs also retain their existing damage modifiers and callbacks. Damage attribution and potion geometry are separate concerns.

Exploratory actual splash impacts demonstrated the difference: healing I/II leaves a Wither at 100 health with Invul 220 or 1 on official 26.3; campaign 82 baseline instead ends at 94/88. Harming I heals to 104 on both. NoAI holds the invulnerability counter fixed for this boundary test. The first fixture's sheep 16 control exceeded official max health 8, so that run is excluded from final validation; the corrected control starts at 8 and expects 2.

The retained fixture/checker exercises twelve cases twice: Invul 220/1/0 crossed with healing I/II and harming I, charging water, sheep harming and zombie healing controls. A protocol 777 headless client throws each real item; the projectile is queried and then moved to break against the arena floor at stationary target feet. The checker requires actual item-use and splash events, pre-impact projectile NBT, initial/final health and Invul, positions, fixed ticks, client/player/environment controls, cleanup and stopped scratch processes. This is world/entity/item/projectile regression coverage; a mocked Rust test would not exercise the bypass.
