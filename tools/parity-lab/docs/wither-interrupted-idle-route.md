# Wither idle navigation on goal interruption

`WaterAvoidingRandomFlyingGoal.stop` now cancels navigation as well as clearing its destination. Vanilla 26.3 inherits this cancellation from `RandomStrollGoal.stop`. When the priority-zero Wither invulnerability goal preempts a running idle stroll, Pumpkin previously kept steering along the obsolete route. The correction uses the same stop call as Pumpkin's existing `WanderAroundGoal`.

Reference: the official 26.3 `WitherBoss.registerGoals`, `WaterAvoidingRandomFlyingGoal`, `WaterAvoidingRandomStrollGoal` and `RandomStrollGoal`, decompiled locally. Fork master is already an ancestor of baseline `8c6eadc03c28c3f74d7e5d5d4167a33d00862ded`. Upstream still lacks this stop. Open PR4092 changes navigation locking in the goal's start method but leaves this stop unchanged; its wider controller/gravity foundation remains outside this patch.

Focused regression: `lab/examples/wither-interrupted-idle-route.json` and `tests/check_wither_interrupted_idle_route.py`. A headless protocol 777 client keeps a sealed scratch arena active. One target-free Wither at a time has controlled movement and flying speed 0.5. The specialized probe steps two ticks until horizontal motion exceeds 0.02 blocks in one sample, bounded at 1200 ticks. It then forces Invul200 and samples 32 ticks. Path length over the final 12 ticks must fall below 0.1 blocks, distinguishing coasting to rest from continued route steering. Ordinary active-flight and initially invulnerable controls are included, twice each. The checks also cover arena bounds, AI state, absence of other mobs, observer mode, tracking, main-head targets, invulnerability countdown, verified tick advances, cleanup and logs. Random stroll destinations and detection times are intentionally independent across targets.

Initial reproduction: vanilla 64/64 checks; baseline 62/64, failing exactly both interrupted-stroll checks. All 444 core library Rust tests, workspace formatting, core all-target/all-feature Clippy and the debug server build passed under the shared Cargo lock, one job, disabled debug information and incremental compilation, MemoryMax=5G, MemorySwapMax=0 and CPUQuota=200%. The existing proc-macro-error2 future-compatibility notice remains. Final identical-fixture comparison: vanilla 64/64, baseline 62/64 with exactly both interrupted-stroll checks failing, patched 64/64. Over the final 12 ticks, horizontal path length was 0.0 blocks in both vanilla and patched trials, versus 1.195 and 0.580 blocks before the correction. Active-flight and initially invulnerable controls passed on all targets. The runs advanced 996, 1050 and 706 controlled ticks respectively, including adaptive route detection and cleanup. Fixture/source/copied-binary hashes, cleanup, clean client/server logs and each server's stop/save markers were checked. The first final assertion expected the word “saved”; the actual log markers are “Saving chunks for level” on vanilla and “Completed save!” on Pumpkin. Correcting that scratch assertion made evidence validation pass without rerunning gameplay.

This is a forced midlife invulnerability transition, not natural Wither construction or a whole fight. NoGravity is requested; remaining controller/gravity and exact trajectory differences are outside this correction. There is no rendered-client or Bedrock evidence. The regression uses actual server worlds rather than a mocked Rust mob; no isolated Rust unit test was added. Human check: in a disposable enclosed arena, let a target-free Wither start strolling, set its Invul to 200, and record it coasting to rest while the timer runs. Decompiled Java, scratch probes, worlds, binaries, credentials and raw reports are excluded from the commit.
