# Wither retaliation on hits rejected by the hurt cooldown

Six rapid hits should provoke the Wither's side heads even though only the first hit reduces health. Vanilla Java 26.3 `WitherBoss.hurtServer` checks its immunities, primes the block-break timer and adds three to each side-head idle counter, then calls `LivingEntity.hurtServer`. Hurt-cooldown rejection happens in that superclass. Pumpkin instead updated retaliation in `on_damage`, which only ran after successful damage. The counters stayed at three instead of eighteen, suppressing both dangerous skull attacks on the next AI step.

The correction adds a default no-op `Mob::on_damage_attempt` hook after the existing cancellable damage events, before shield and hurt-cooldown checks. Only Wither overrides it. Its existing timer/counter updates move to that hook, so accepted hits increment once and cooldown-rejected hits also count. Boss/source immunities, general entity invulnerability and plugin cancellation still prevent the update. Other mobs retain their existing successful-damage callback and receive no new effects.

## Reference and overlap

The reference is the official Minecraft Java 26.3 server, decompiled outside Git. The call chain inspected was `WitherBoss.hurtServer`, Pumpkin's mob damage dispatch and `LivingEntity::damage_with_context`, including event cancellation, absorption and cooldown rejection. The change preserves Pumpkin's damage-event contract; vanilla has no native plugin events.

Fork master `65bca3f7f36af3b4f5e32ac24ed9abd71c930844` was fetched and is already an ancestor of the campaign branch. Read-only upstream master `998c3f872c39bb68167c6f2a47799730a23aa751` retains the successful-damage hook. [Mob AI tracking #3468](https://github.com/Pumpkin-MC/Pumpkin/issues/3468) and [the tracker](https://pumpkinmc.org/tracker/) were inspected; the spawn-window and ranged-attack entries are already addressed by earlier campaign commits.

Open [#4092](https://github.com/Pumpkin-MC/Pumpkin/pull/4092), head `5c8cf6c268c6ed158cdc0dc394527b77159ff586`, changes the AI foundation and other Wither tick responsibilities but does not move these damage side effects. Open [#3835](https://github.com/Pumpkin-MC/Pumpkin/pull/3835), head `3640e87c42efc5d582ae10d797c891a327067760`, concerns projectile flight, attribution and accepted-hit effects. Neither supplies this correction. Existing flight, explosion-scaling and loot overlap leads were left out. No upstream write action was taken.

## Regression and validation

The committed `wither-hurt-cooldown-retaliation.json` fixture uses a forced-loaded scratch arena and a connected headless protocol-777 client. NoAI pauses attack decisions while six or seven damage attempts happen in one frozen tick. The first hit reduces health to 299; later attempts are rejected. After AI resumes for one tick, both side heads should shoot dangerous skulls. Five-hit and single-hit cases remain below the threshold. Drowning immunity, spawn invulnerability and general invulnerability remain silent. The fixture also verifies no ordinary skulls, health, position, NoAI suppression and entity cleanup. Each case starts with an entity-removal barrier.

An initial two-trial probe reproduced both dangerous skulls on vanilla and no skulls on baseline `ae5ddbdde8e51525d91e3e74bfcb46076fdd4867`, with all four controls passing. The expanded committed fixture passed 104/104 checks on vanilla and 100/104 on baseline Pumpkin in two trials. The four failures are exactly the dangerous-skull checks after six- and seven-hit bursts; all health, threshold, immunity and cleanup controls pass. The fixture and measured-command hashes match. All 443 core Rust library tests, workspace formatting, core all-targets/all-features Clippy and a full debug server build passed. Cargo ran under the shared lock with one job, disabled debug info/incremental compilation and the required 5-GiB/no-swap/200%-CPU scope. The copied binary and all three Rust source hashes match the verification record. Patched Pumpkin passed 104/104 checks across the same two trials, matching vanilla. The final assertion script verifies identical fixture and measured-command hashes, 217 controlled fixture ticks per trial, the copied binary hash and all three source hashes. All three comparison server processes stopped; both Pumpkin logs contain completed save/stop markers and no final server/client log contains an error or panic. Vanilla full-save completion remains unverified within the existing shutdown grace. The final upstream overlap refresh found the same PR heads and no duplicate correction. Raw reports and hashes remain in local task-38 artifacts outside Git.

## Limits

The stimulus uses controlled damage commands and one resumed AI tick; it does not reproduce a natural group melee fight or prove full boss parity. No rendered-client capture is provided. Plugin cancellation is preserved by hook placement, but no plugin listener is exercised live. Arbitrary damage modifiers, dead bosses, shield blocking and the full block-break lifecycle are outside this bounded check. Existing shared flight/controller work is not changed. Existing proc-macro-error2 future-compatibility, Java native-access/Unsafe, offline-mode and development-build warnings remain.
