# Wither End gateway activation

Withers could activate End gateways despite being ineligible to use portals. Vanilla 26.3 `WitherBoss.canUsePortal(boolean)` always returns false, and `EndGatewayBlock.entityInside` checks eligibility before setting portal state or triggering the gateway cooldown. Pumpkin's gateway collision handler lacked the exclusion: Wither contact emitted a cooldown/beam block event. The correction rejects Wither contact before cooldown, destination lookup or teleport. Other entity types retain the original path.

The focused fixtures `lab/examples/wither-gateway-cooldown-{full,powered,spawning}.json` give slight horizontal motion to full-health, powered and spawn-invulnerable Withers inside a destinationless gateway. The decoded packet oracle requires no Wither cooldown event at (5,80,5). Each boss remains in the entrance block with unchanged health and spawn state. A later sheep stays healthy; its events are retained as context without a vanilla cooldown expectation. NoAI/NoGravity isolate collisions from attacks, healing and flight. Eight total ticks stay below the periodic gateway attention interval. Two repetitions use verified frozen ticks, cleanup and a connected headless protocol 777 client.

The final reference passes 54/54 focused checks on vanilla and 48/54 on baseline Pumpkin. Exactly the six Wither cooldown assertions fail on baseline: one decoded cooldown/beam event per contact, versus none on vanilla. Both actor types were present in decoded spawn packets; identical fixture/stimulus hashes, 48 verified gameplay ticks per server, client presence, cleanup and stopped scratch processes were checked. The three health/spawn states each repeat twice. The sheep packet stream remains outside the parity oracle.
