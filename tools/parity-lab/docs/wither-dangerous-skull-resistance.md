# Dangerous Wither skull block resistance

Dangerous blue skull impacts previously used each block's normal blast resistance, leaving obsidian and crying obsidian intact. Vanilla caps resistance at 0.8 for blocks accepted by `WitherBoss.canDestroy`. Ordinary skulls and Wither-immune blocks retain their original resistance.

The default explosion calculator now passes the maximum block/fluid resistance through the source entity's `get_block_explosion_resistance` hook. The default entity implementation preserves resistance; the Wither skull implementation applies the cap only when dangerous and when the existing Wither destruction predicate accepts the block. Empty air remains absent from the resistance calculation. Existing explosion attribution, cancellation, damage, packets, drops and mob-griefing selection continue through their existing paths. Explicit custom calculators still control their own resistance.

Vanilla 26.3 review follows `WitherSkull.onHit/getBlockExplosionResistance`, `ServerExplosion.makeDamageCalculator/calculateExplodedPositions`, `EntityBasedExplosionDamageCalculator.getBlockExplosionResistance`, the base calculator's block/fluid maximum, and `WitherBoss.canDestroy`. No upstream implementation was copied. Fetched fork master `65bca3f7f36af3b4f5e32ac24ed9abd71c930844` is already an ancestor. Fetched upstream `998c3f872c39bb68167c6f2a47799730a23aa751` has no subsequent correction for these files; no additional relevant master fixes require integration.

The [permanent regression fixture](../lab/examples/wither-dangerous-skull-resistance.json) drives five isolated skulls into individual blocks in a scratch arena: ordinary obsidian, dangerous obsidian, dangerous bedrock, dangerous obsidian with mob griefing disabled, and dangerous crying obsidian. Every case checks the starting block, loaded dangerous flag, projectile consumption after four verified ticks, and the resulting block. Each server runs two identical trials with a connected headless protocol 777 client.
