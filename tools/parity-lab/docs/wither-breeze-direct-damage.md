# Wither breeze wind-charge direct damage

Powered Withers incorrectly rejected direct breeze wind-charge sources. Vanilla 26.3 `WitherBoss.hurtServer` rejects `AbstractArrow` and `WindCharge` instances at or below half health. `BreezeWindCharge` and `WindCharge` are separate subclasses of `AbstractWindCharge`; the breeze class does not inherit the player charge's immunity. Pumpkin's explicit entity-type list included both charges. This patch removes only the breeze entry.

The regression fixture `lab/examples/wither-breeze-direct-damage.json` exercises actual server damage handling through `/damage`, using summoned source entities. Eleven cases cover breeze and player charges at 149, 150 and 151 health, a noncharge source with the same damage type, separate sheep/Wither/friend attackers, and the spawn-invulnerability window. Frozen ticks and NoAI prevent projectile movement, bursts, healing and attacks from confounding the direct-source check. Health changes are gameplay observations; this fixture does not exercise projectile collisions or a natural Breeze attack.

Before the change, two repetitions pass 44/50 checks on Pumpkin and 50/50 on vanilla. The six failures are breeze sources at 149 and 150 health and a breeze source with a sheep attacker, repeated twice. Vanilla accepts one damage point before armor: health becomes 148.14 or 149.14. Baseline Pumpkin leaves those bosses at their original health. At 151 health, both accept breeze and player charges and reach 150.14. Player charges remain blocked at 149/150; Wither/friend attackers and spawn invulnerability remain blocked. All eleven numeric final-health results are compared against vanilla, alongside identical fixture and stimulus hashes.

All 443 core Rust library tests, workspace formatting, core Clippy with all targets/features and the full debug server build passed under the shared build lock, one build job, disabled debug info/incremental compilation and required memory/CPU limits. The existing `proc-macro-error2` future-compatibility warning remains. The focused gameplay fixture supplies regression coverage for the type-list correction; no duplicated-list Rust unit test was added.

Patched Pumpkin passes 50/50 checks, matching vanilla, including all eleven numeric final-health values in each of two repetitions. Baseline passes 44/50 with exactly the six expected failures. Fixture and gameplay-command hashes match across all three runs; built source and baseline/patched binary hashes were verified. Connected headless protocol 777 clients, successful entity cleanup and stopped scratch processes were verified. Server and client logs contain no errors or panics. Complete save/shutdown markers were not observed within the existing harness grace period on any of the three servers. Existing Java native/Unsafe warnings remain.

Evidence is retained in `artifacts/jaron-wither29-validation.json`, `artifacts/jaron-wither29-log-validation.json`, `artifacts/jaron-wither29-source-provenance.json`, `artifacts/jaron-wither29-verify.json` and the arena reports linked there.
