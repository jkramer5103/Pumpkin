# Wither skull wall placement

A real side-face placement of a Wither skeleton skull produced a floor skull in Pumpkin. Official Java 26.3 produces a wall skull facing away from its support. The Wither block handler only registered the standing variant and always delegated to floor-skull placement.

The Rust correction selects floor versus wall using vanilla's nearest-looking order, gives the clicked support priority when placing into an adjacent position, and searches all horizontal supports before choosing between the wall candidate and the floor. Wall facing and initial powered state use generated block properties. The wall variant now shares the existing skull block-entity and Wither construction handler, so placing the final wall skull still summons the boss. Other skull species and shared block/item placement code are outside this change.

Reference: local decompiled official 26.3 StandingAndWallBlockItem.getPlacementState, BlockPlaceContext.getNearestLookingDirections, WallSkullBlock.getStateForPlacement, WitherWallSkullBlock.setPlacedBy, and WitherSkullBlock.checkSpawn. Fetched upstream 44d881c32 retains floor-only placement and registration. Open wall-skull/construction PR searches found no overlapping correction. Sound categories overlap PR3988, skull effect rejection overlaps PR3835, and the inspected cobweb exemption already exists; none was changed. Provider-rejected candidates remain excluded.
