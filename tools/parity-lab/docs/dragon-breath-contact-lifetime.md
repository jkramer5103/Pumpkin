# Dragon breath lifetime under victim contacts

Sitting dragon breath could disappear after affecting a small crowd, leaving later victims unharmed. The breathing phase passed `-100` as the cloud's duration change per victim, exhausting its 600-tick lifetime after six accepted contacts. Vanilla `DragonSittingFlamingPhase.doServerTick()` creates an `AreaEffectCloud` whose `durationOnUse` remains zero. Its server tick therefore preserves the configured duration when a victim receives an effect.

The dragon-specific cloud creation now passes zero for duration on use. The shared cloud implementation and other cloud producers are unchanged. This fixes contact-driven exhaustion; the existing initial duration, radius, radius changes, placement, particles, owner attribution, damage implementation and sitting phase cycle remain separate discrepancies.

The regression `lab/examples/dragon-breath-contact-lifetime.json` runs two isolated trials with a protocol 777 headless client. It summons a real phase-5 dragon, advances ten ticks to emit breath, pauses the dragon with NoAI and moves it away from its cloud. Six distinct stationary sheep are placed at the actual cloud center. After twenty ticks each must have 5 health and the cloud must still exist. They are removed and a seventh sheep is placed at the saved cloud center, independently of whether the cloud survived; after another twenty ticks it must also have 5 health. A marker preserves that position. Both the dragon and sheep use distinct UUIDs across trials. The fixture never edits the cloud's properties.

All 460 core Rust library tests, workspace formatting, core all-targets/all-features Clippy and the debug server build passed under the shared build lock with one job, debug info and incremental disabled, 5 GiB memory, no swap and 200% CPU caps. Vanilla and patched Pumpkin each passed 27/27 focused checks over two trials; baseline passed 21/27. Both baseline trials damaged all six initial sheep, then lost the cloud and left the seventh sheep at 8 health. Patched Pumpkin and vanilla retained their cloud and reduced the seventh sheep to 5 health. Identical stimulus commands, exact tick deltas, client presence and fixture/source/binary hashes were verified. This live regression catches a real behavioral failure; no redundant constant-only Rust test was added.

All three final scratch processes stopped. Both Pumpkin save completions were verified; vanilla logged dimension saving without a final completion marker during the harness grace. No server error/panic lines were found. Existing proc-macro-error2 future-compatibility and Java native/Unsafe warnings remain. An initial reference run is retained and excluded: it left the dragon next to its own cloud, allowing another independent cloud eligibility discrepancy to consume one contact. The final fixture moves the NoAI dragon away before testing sheep.
